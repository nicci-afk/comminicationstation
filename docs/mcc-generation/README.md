# Gmail generation cutover draft

This draft installs a **durably paused** queue and mutation fence. Merging,
applying SQL, deployment and activation require separate approval. Do not deploy
repository workers directly: the versioned materializer preserves their distinct
prompt variant and all 19 files, alongside the 34-file API bundle.

## Validation-only CI

The historical checkpoint job explicitly checks out its previously approved main
commit. Its old manifest and test assertions are preserved. A separate generation
job checks the PR's exact candidate:

1. Materializer tamper tests and all 231 local regressions
2. Both full Edge graphs, real dependencies and baseline-relative Deno diagnostics
3. All existing containment runtime tests against tagged candidate sources
4. All existing Gmail runtime assertions with a separate generation RPC fixture
   adapter. This retains the checkpoint failure semantics; that fixture is not
   the real generation database protocol
5. Independent native PostgreSQL sessions, real pgmq and PostgREST, exact retained
   canonical ingest, and an exact-candidate Edge smoke against that schema

The native runner observes `pg_blocking_pids`/lock waits for each ordered race.
It checks installation rollback, in-flight legacy bodies, role/header propagation,
canonical duplicate ingestion, queue and receipt ownership, pause/reclaim/finish,
lock timeout retry, stale ACK/dead-letter, unrelated queues, ACLs, exact cutoff
activation and provider-blocked Edge execution. It does not enumerate every
possible interleaving or prove exactly-once delivery.

Only disposable local Supabase stacks are used. No production secrets are loaded,
no new GitHub secret is required, no cron migrations are installed, database pokes
are stubbed, and application transport wrappers reject external non-synthetic
requests. Workflow permissions remain `contents: read`.
